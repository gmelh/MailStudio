# Sections

The section types available to every email, shared by the server renderer and the editor.

- `sections.json` — each type's label, icon, fields and defaults.
- `templates/<type>.mjml` — the type's markup: MJML with [Mustache](https://mustache.github.io/mustache.5.html) placeholders.
- `templates/_document.mjml` wraps the sections; `templates/_compliance.mjml` is added when an email has no Footer or Unsubscribe section.

## What a template can use

| Name | Value |
| --- | --- |
| `{{s.<field>}}` | The field's value, HTML-escaped |
| `{{{s.<field>_html}}}` | Textarea fields: paragraphs and line breaks as safe HTML |
| `{{#s.<field>_lines}}{{.}}{{/s.<field>_lines}}` | Textarea fields: one item per non-empty line |
| `{{#s.<field>_ok}}…{{/s.<field>_ok}}` | URL and image fields: shown only when the URL is a valid http(s) URL |
| `{{#s.<field>_is_<option>}}…{{/…}}` | Select fields: shown when that option is chosen |
| `{{brand.<name>}}` | Brand values: colours, `fontSize`, `padding`, `width`, `fonts.heading/body/small`, plus `h2`, `h3`, `small` style strings, `muted` and `divider` colours |
| `{{merge.unsubscribe_url}}` | Becomes each recipient's own unsubscribe link at send time |

Number fields are clamped to their `min`/`max`; select fields always hold a listed option;
an image field with `"fallback": "brand.logo"` uses the brand logo when empty.

Rules: templates are logic-free, so they can't run code, and every value is escaped unless a
`_html` field (generated by trusted code) is used with triple braces. Owners' merge tags such as
`{{first_name|there}}` in their content pass through rendering untouched and are filled in per recipient.
